# 봉봉봉 (상점 페이지 `/shop/`)

디스코드 서버 "어서오십쇼!이길드에!" 친구들한테 이놀아안이 유료로 부탁을 받는 가게다. 블로그 안에서 이 페이지만 예외로, 게임 상점처럼 움직임과 연출이 많다. 홈의 링크 줄(`content/_index.md`)에서 들어온다.

- 공개 주소: https://innollia.github.io/shop/ (2026-10-28 기준 아직 배포 전)
- 내부 가격 정책(비공개): `C:\projects\_plans\shop-pricing.md`. 이 저장소는 공개라서 내부 견적 숫자는 여기 두지 않는다.

## 파일

```text
static/shop/
  index.html              뼈대: 간판, 주인 말풍선, 진열대, 상세 패널, 장바구니, 주문서(영수증)
  shop.css                전체 스타일. 색·글꼴은 :root 변수
  shop.js                 상품·가격·동작 전부 (아래 표)
  dialogue.js             말풍선 대사 전부(사용자가 직접 고치는 파일). 헛소리(idle)는 문장생성기 accept가 더한다
  img/                    art/의 그림을 여백 잘라 webp로 만든 것(층 그림 bg_*·jaw_*·load_*는 자르지 않음)
  supporters.json         똘라따무(후원자 이름 칸). 워크플로가 만든다. 손으로 고치지 말 것
  supporters_manual.json  계좌로 직접 받은 후원. 손으로 적는다
  carts/<id>.html|.js     PICO-8 웹 내보내기 결과 (bounce, curser2, squashy, train, eatkano)
  carts/*.png             카트 라벨 그림
  tin/<id>/               시간 막대에 쓰는 게임 캡처 8개와 manifest.json (나머지 7개는 design/tin_unused/)
  ordername.js            주문번호(한글 10글자) 만드는 곳과 단어장
  art/                    그래피티 화풍 그림 에셋 (작업 중, art/README.md)
tools/bmc_supporters.py   BMC 후원 + 직접 입금 → supporters.json
.github/workflows/supporters.yml   (로컬에만 있음, 저장소에 안 올림) 위 스크립트를 3시간마다 돌리는 옛 방식
design/                   공개되지 않는 작업물 (테마 시안, 원본 캡처)
```

## 주문 흐름

1. 손님이 상품을 골라 담고 "주문하기"를 누르면 주문서 한 장이 뜬다. 담은 것 확인·수정·빼기(되돌리기 있음), 합계 (후불), "연락받을 디스코드 사용자명"(필수, 표시 이름 말고 @아이디), 큰 "디스코드로 주문 보내기" 버튼만 있다. 결제 안내·주문서 복사·미리 보기·닉네임 칸은 없앴다(후불이라 결제는 결과물 뒤 DM에서). 장바구니·사용자명·주문번호는 브라우저에 남는다.
   - 주문번호는 `ordername.js`가 만든 한글 10글자다. 무작위 초성 10개를 뽑고 그 초성에 맞는 단어로 채우는데, 긴 단어가 들어가는 쪽을 고른다(예: 곰탕폐지수수돗물통합). 장바구니 하나에 번호 하나이고, 보내면 새 번호가 된다. 단어장은 서버 말 + 국립국어원 「한국어 학습용 어휘 목록」 명사(공공누리 1유형).
2. 보내면 웹후크가 이놀아안 **개인 서버**의 포럼 채널(guild 1533421689558270152)에 `주문번호 · 첫 상품 이름[ 외 N]` 스레드를 연다. 첫 메시지는 `디스코드 사용자명: …` 줄과 코드블록(`[봉봉봉 주문서] <번호>`, 상품 줄 `N. 이름 (요약): 가격`, 합계)이다. 손님은 그 서버에 없으니 스레드 링크는 주지 않고, 이놀아안이 그 사용자명으로 DM해서 조율한다. ss0 DM 해금 주문이면 Eve가 같은 사용자명으로 봇이 있는 서버들에서 계정을 찾아 스레드에 해금 버튼을 단다.
3. 결과물을 넘긴 뒤 손님이 입금한다(후불).

**손님 찾기 (Eve, eve-scene-runtime 3438cbb).** 주문서 칸은 "연락받을 디스코드 이름"이고 서버 닉네임·표시 이름·사용자명 아무거나 받는다. 상점은 NFKC 정규화 후 제로폭·제어문자와 앞뒤 공백만 지우고 64자로 잘라 `디스코드 사용자명:` 줄에 그대로 보낸다. Eve는:
- ss0 봇이 있는 서버 8곳의 모든 멤버, 멤버마다 이름 세 개(서버 닉네임, 전역 표시 이름, 사용자명)를 비교한다. 멤버 목록은 10분 캐시.
- 오염 정리: NFKC → 제로폭·제어·양방향 문자 제거 → 동형이의 문자 정리(TR39 confusables, `confusables` github.com/gc/confusables) → 소문자 → 앞 @ 제거 → 공백과 `_ . - · |` 제거.
- 오타 허용: 한글은 자모로 분해(`es-hangul`, github.com/toss/es-hangul)한 뒤 레벤슈타인 거리(`fastest-levenshtein`). 유사도 = 1 − 거리 ÷ 긴 쪽 길이, 정리 후 같으면 1.
- 0.75 미만은 버린다. 1등이 0.9 이상이고 2등과 0.08 넘게 차이 나면 그 한 명만 해금 버튼. 아니면 1등과 0.15 이내 최대 5명을 버튼으로 보여 주고 운영자가 고른다. 아무도 없으면 "사용자명을 확인해 주세요".
- 손님이 봇과 같은 서버에 한 곳도 없으면 찾지 못한다.

웹후크가 실패하면 그때만 "이놀아안에게 DM" 링크를 보여 준다.

**주의:** 웹후크 주소는 공개 JS에 그대로 보인다. 누가 마음먹으면 그 채널에 도배할 수 있다. 그런 일이 생기면 디스코드에서 웹후크를 새로 만들고 `DISCORD.webhook`을 바꾼다. 웹후크 대상은 반드시 **포럼 채널**이어야 한다. 일반 채널이면 `thread_name` 때문에 전송이 실패한다.

## 후원 관리 (똘라따무: 후원자 이름 칸)

**입금 확인과 ss0 DM 해금은 All Tomorrow 콘솔에서 한다** (https://dp7.tailc5ef02.ts.net/#/shop-pay, 메뉴 "봉봉봉 → 입금 확인", 사용자 혼자 쓰는 화면). 사용자가 직접 정했다(2026-10-28).

- 주문번호, 디스코드 닉네임, 금액, 수단, 공개 이름(비우면 익명), 한마디를 넣고 확인하면 이 저장소의 `supporters_manual.json`에 한 줄이 추가되고 `supporters.json`도 다시 만들어진다. 콘솔이 이 두 파일만 커밋·push한다. 명예의 전당은 `supporters.json`을 읽으므로 hugo 배포 뒤 반영된다.
- 주문번호와 닉네임은 콘솔 내부 기록에만 남고 공개 파일에는 들어가지 않는다. 잘못 넣은 건은 콘솔의 "되돌리기"로 뺀다.
- DM 해금은 Eve가 주문 스레드에 다는 승인 버튼으로 한다. 장바구니에 ss0 DM 해금이 있으면 주문서가 디스코드 사용자명(@ 빼고 소문자)을 필수로 받는다. 웹후크 첫 메시지의 `주문자:` 줄 바로 다음에 `디스코드 사용자명: 사용자명` 줄이 들어가고, Eve가 그걸로 계정을 찾는다. Firestore나 서비스 계정 키는 쓰지 않는다.
- 블로그 Firebase에 관리 페이지를 두는 안은 철회됐다. 블로그 Firestore는 댓글에만 쓴다.

- (옛 방식, 저장소에 올리지 않음. 콘솔이 같은 파일을 커밋하므로 둘이 부딪히지 않게 뺐다) `supporters.yml`이 3시간마다(그리고 Actions 탭에서 수동 실행으로도) `tools/bmc_supporters.py`를 돌린다. 이 스크립트는 BMC 후원 목록과 `supporters_manual.json`을 합쳐 `supporters.json`을 만든다. 바뀐 게 있으면 커밋하고 `hugo.yaml` 배포를 직접 부른다. GITHUB_TOKEN으로 한 push는 배포를 자동으로 깨우지 않기 때문이다.
- 저장소 Secrets에 `BMC_TOKEN`이 있어야 BMC 쪽을 가져온다. 없으면 직접 입금 기록만 쓴다.
- 공개 저장소라서 이메일과 결제 정보는 저장하지 않는다. 비공개 후원은 이름을 "익명"으로 바꾸고, 환불된 후원은 뺀다.
- 직접 입금 기록 형식: `[{"name": "비빔", "amount": 5000, "currency": "KRW", "note": "", "date": "2026-10-28", "source": "bank"}]`

## PICO-8 게임 다시 내보내기

PICO-8은 `C:\Program Files (x86)\PICO-8\pico8.exe`에 있다. 원본 카트는 `C:\projects\carts`에 있다.

```bash
"/c/Program Files (x86)/PICO-8/pico8.exe" baunce.p8 -export "C:/projects/innollia.github.io/static/shop/carts/bounce.html"
```

`__label__`이 없거나 깨진 카트는 명령이 성공으로 끝나도 파일을 만들지 않는다. curser_2, squashy, train, eat는 원본을 건드리지 않고, 단색 라벨을 붙인 사본(스크래치 폴더)으로 내보냈다. 카트 하나당 js가 약 1.6MB다.

## 화면을 바꿨으면: 클린룸 점검

코드를 아는 사람이 확인하면 정답 경로로만 눌러서 문제를 놓친다. 바꾼 뒤에는 맥락 없는 에이전트에게 주소와 "주문해 봐"만 주고, 화면만 보며 손님처럼 끝까지 따라가게 한다. 디스코드로 실제 보내는 버튼만 금지한다. 테마가 정해지기 전에는 겉모양(글꼴·색·몇 px 밀림) 문제는 보고받지 않는다.

UI 참조(트릭컬, 엔터 더 건전, 스매시 얼티밋, 음식점 키오스크) 조사는 `docs/ui-research.md`에 있다. 처음 요청 때 받은 스킬(frontend-design, ui-ux-pro-max, GSAP, game-ui-frontend, webapp-testing)은 `.claude/skills/`에 받아 두었다(깃에는 안 올림).

- **그림 에셋**: 별도 세션 "봉봉봉 상점 그림 에셋"이 `static/shop/art/`에 그리고 있다. 주인 캐릭터는 두 벌이다. 하나는 새 캐릭터(`keeper_*`), 다른 하나는 사용자 자캐 `C:\projects\ssss0.png`를 재해석한 것(`keeper_oc_*`)이다. 사용자가 둘을 비교해 고른다. 다 되면 지금의 임시 벡터 그림(`ICON`, `KEEPER_SVG`, `.coin`의 치아 SVG)을 바꾼다.
- **게임 캡처**: 끝. 시간을 받은 8개만 `static/shop/tin/`에 남겼다(마법사 1h, 자동 전투 RPG 3h, 쌓고 내려가는 사막 8h, 균열 조합장 14h, GuineaStar 20h, 플랫포머 26h, 선이 되기 전에 28h, flesh-pit 70h). 9번 마법사는 "가장 짧은 시간"이라 1h로 넣었다. 선이 되기 전에는 웹 빌드로 다시 찍었다.
- **ss0 DM 해금**: eve-scene-runtime `7b4f650`에 배포됐다. 결제를 확인한 뒤 소유자가 디스코드에서 `/unlock_dm user:@구매자`를 실행한다. 회수는 `/revoke_dm user:@구매자`, 해금 목록은 `/dm_unlocks`로 본다. 세 명령 모두 소유자만 쓸 수 있고, 답은 실행한 사람에게만 보인다. 구매자는 횟수 제한 없이 일반 대화만 할 수 있고, 슬래시 명령·버튼·제어판은 못 쓴다. 상점 안내 문구는 반영했다. 실제 계정으로 해금 → DM → 회수 순서를 확인하는 일이 남았다(이브 세션이 사용자에게 요청함).
- **BMC 연동**: developers.buymeacoffee.com(옛 API)에는 "더 이상 관리하지 않음" 표시가 붙었고, 웹후크로 옮기라고 안내한다. 웹후크는 BMC가 우리 주소로 POST를 보내는 방식이라 정적 사이트(GitHub Pages)로는 받을 수 없고, 받는 서버가 따로 있어야 한다. 옛 API에서 토큰이 아직 발급되면 지금 워크플로가 그대로 돈다. BMC 웹후크 수신은 All Tomorrow 콘솔에 준비돼 있고(확인 대기 → "이 후원으로 채우기"), 공개 주소는 사용자 확인 뒤에 켠다. `supporters.yml`(옛 API 워크플로)은 저장소에 올리지 않았다.
- **글 읽어주기 단가 확정**: 지금은 시범가 4단계다.
- **배포 전 확인**: 휴대폰 화면, 디스코드 실제 주문 전송 시험 한 번.
