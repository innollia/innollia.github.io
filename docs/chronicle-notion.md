# 메모 연대기와 쇠판 합치기

블로그 메모 연대기(`/chronicle/`)와 쇠판 노션-디스코드 포럼을 메모 한 벌로 쓴다.
포럼 동기화 자체는 `eve-discord-runtime/docs/NOTION_DISCORD_FORUM_SYNC.md`에 있다.

## 지금 상태 (2026-11-04 확인)

| | 연대기 | 쇠판 |
| --- | --- | --- |
| 내용 | 739편: 삼성노트 306, 스크리브너 118, 디스코드 315 | 원장 66판, 기록 230편 (백필 전 수치) |
| 범위 | 2020-06 ~ 2026-09-26, 9월 27일에 굳힘 | 2025-11 ~ 현재, 계속 늘어남 |
| 공개 | 공개 저장소에 올라가 누구나 읽음 | 비공개 서버와 노션, 무검열 1:1 |

- 연대기의 디스코드 315편 중 313편이 `쇼-비즈니스-맙소사`, 곧 쇠판과 묶인 포럼의 글이다. 이 부분이 겹친다.
- 연대기는 그날 뒤로 갱신되지 않았다. `data.json`을 만든 생성기는 어디에도 남아 있지 않다.
- 봉인 52편을 고른 규칙도 남아 있지 않다. 뷰어에 복호화 코드가 없어 암호문은 보여 주지 않는다.

## 저장 위치

**메모의 정본은 노션 쇠판 원장·기록 하나다.** 디스코드 포럼은 쓰고 읽는 창구, 블로그는 공개용 읽기 전용 화면이다.

```
디스코드 포럼 ⇄ 노션 쇠판 (정본) → 메모 연대기
             (포럼 동기화)      (이 문서, 읽기만)
                                ↑
                  9월 27일 스냅샷 739편 (그대로)
```

- 블로그는 노션을 읽기만 한다. 블로그에서 노션이나 포럼으로 돌아가는 길은 없다.
- 옛 메모 739편은 `static/chronicle/data.json`에 그대로 둔다. 삼성노트·스크리브너 424편을 쇠판에 넣지 않는다.
  넣으면 방안 B가 모든 판을 포럼에 올리므로 포럼에 옛 글이 쏟아진다.
- 원본 파일은 전처럼 `C:\projects\memos`에 남는다.

## 겹치지 않게 하는 방법

규칙은 하나다. **2026-09-27 00:00(KST) 앞의 글은 스냅샷이, 그 뒤의 글은 쇠판이 맡는다.**

- 포럼 백필로 옛 글이 쇠판에 들어와도 날짜가 앞서므로 연대기에 다시 들어가지 않는다.
- 스냅샷의 내용과 봉인은 건드리지 않으므로, 이미 공개된 범위가 바뀌지 않는다.
- 새 메모의 `id`는 노션 페이지 id에서 만들어 빌드마다 같다. `/chronicle/#<id>` 링크가 유지된다.

## 공개 기준

포럼은 무검열이고 블로그는 공개다. 그래서 **표시한 것만 나간다.**

`쇠판 기록`과 `쇠판 원장`에 `블로그` 선택 칸을 둔다. 값은 `공개`, `봉인` 둘이다.

| 값 | 연대기 |
| --- | --- |
| 빈칸 | 안 나감 |
| `공개` | 제목·본문·판 이름이 나감 |
| `봉인` | 봉인 카드만 나감. 날짜와 글자 수뿐이고, 제목과 암호문은 싣지 않음 |

- 기록의 칸이 먼저다. 기록이 비었으면 판의 칸을 따른다. 판에 `공개`를 걸면 그 판의 새 기록이 저절로 나간다.
- 칸을 지우면 다음 빌드에서 사라진다. 다만 그 사이 저장소 밖에서 복사된 것은 되돌릴 수 없다.
- 포럼에서 지운 기록(`deleted_on_discord`)과 노션 휴지통의 기록은 나가지 않는다.
- 공개 카드에서 이미지와 서명 주소(디스코드 CDN, 노션 S3)는 뺀다. 서명 주소는 만료되고 그 자체로 공개하면 안 된다.

## 동작

`tools/build_chronicle.py`를 배포 때 실행한다. 갤러리와 같은 방식으로, 결과물은 사이트에만 올리고 커밋하지 않는다.

- 배포는 push, 수동 실행, 6시간마다 돈다.
- GitHub 비밀값 `CHRONICLE_NOTION_TOKEN`을 쓴다. 읽기 권한만 준 노션 연동으로 쇠판 두 곳만 연결한다.
- 토큰이 없거나 노션이 실패하면 경고만 남기고 스냅샷으로 배포한다. 블로그 배포를 막지 않는다.
- 포럼 동기화 코드를 고치지 않는다. poller는 내용 해시가 다를 때만 다시 보내므로 `블로그` 칸을 바꿔도 디스코드는 그대로다.
  노션을 읽기만 하므로 poller/listener 단일 인스턴스 조건에도 영향이 없다.

## 한계

- 9월 27일 앞에 노션에서 직접 쓴 기록은 연대기에 들어가지 않는다.
- 새 메모의 주제 분류는 `유형`을 옮긴 것이고, 나머지는 `기타`다.
- 스냅샷의 디스코드 글을 포럼에서 지워도 연대기에는 남는다. 빼려면 `data.json`을 고친다.
- GitHub는 저장소 활동이 60일 없으면 예약 실행을 멈춘다. 그때는 push나 수동 실행으로 다시 켠다.
